# Scribae v0.2.0

## Summary

Shipped baseline, recorded after the fact. Scribae is a local-first CLI that turns a Markdown
note into a publishable SEO content package. Each pipeline stage is its own command reading and
writing plain files, so a human reviews and edits between stages. All generation goes through one
OpenAI-compatible endpoint (default: local Ollama); translation runs locally on CPU. This spec
states what already exists so later specs only carry new commitments.

## Goals

- One command per pipeline stage, resumable from files on disk, with a human in the loop.
- Provider-agnostic generation behind a single OpenAI-compatible seam.
- Structured LLM output validated strictly, never trusted as free text.
- Runs fully local: local endpoint for generation, CPU-only models for translation.

## Potential Features

### Content Pipeline

`idea` -> `brief` -> `write` -> `meta` turns a note into ideas, a validated SEO brief
(keywords, outline, FAQ, metadata), a draft, and finally publication frontmatter.

### Draft Review Loop

`feedback` critiques a draft against its brief without rewriting it; `refine` applies targeted
improvements against the same brief. Together they let a draft improve without regeneration.

### Translation

`translate` renders Markdown into another language while preserving formatting, using local MT
(Marian for direct pairs, NLLB for the rest, deterministically routed) followed by an optional
LLM post-edit pass.

### Project Configuration

`init` writes a `scribae.yaml` through a guided questionnaire. The project config carries site
name, domain, audience, tone, keywords, language, and allowed tags into every prompt, with
defaults when no config exists.

### Language Handling

Output language is resolved from explicit flags, note front matter, or project config, and
generated text is checked against the expected language rather than assumed.

### Deterministic Output Controls

`--seed` and `--top-p` on every LLM command, plus separate post-edit controls on `translate`,
make runs reproducible enough to compare.

## Caution

- LLM quality is bounded by whatever endpoint is configured; the default is a small local model.
- Translation quality depends on local MT models; the post-edit pass masks, but does not remove,
  MT weaknesses.
- Prompts are deterministic templates, so prompt changes are behavior changes.

## Recommendation About LLM Support

Stay provider-agnostic: one OpenAI-compatible seam configured by environment variables, async
calls with a timeout and bounded retries, no provider-specific SDKs and no hosted dependency.

## Explicitly Excluded

- Publishing to, or integrating with, any CMS.
- A hosted or multi-user service surface.
- Fully autonomous end-to-end runs with no human review between stages.
