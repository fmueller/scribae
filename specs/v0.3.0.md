# Scribae v0.3.0

## Summary

Active spec. Covers work landed since the 0.2.0 release plus the hardening needed to cut
0.3.0: the translation backend moved off the removed `transformers` pipeline task onto
direct seq2seq models, translation input handling stopped silently truncating and is now
memory-bounded, note titles use validated string fallbacks, and the dependency floor was
raised (typer 0.27, mypy 2.3, python-frontmatter 1.3). Unit regression coverage for input
limits, bounded batches, and title fallbacks is already present. Real-model validation and
release hygiene remain tracked separately.

## Goals

- Ship a correct, memory-bounded translation path on the seq2seq backend.
- Keep the repository releasable: changelog, version, and docs matching the code.
- Keep the checks green under the pinned toolchain (ruff, mypy strict, pytest).

## Potential Features

### Translation Backend Migration

`transformers` removed the `translation` pipeline task; `translate/mt.py` now drives
seq2seq models directly. The `transformers` seam is typed and test doubles are shared via
`tests/mt_fakes.py`.

### Translation Input Safety

The MT backend tokenizes without truncation and rejects a block exceeding a meaningful
model token limit with an error naming the model and limit. It does not automatically split
an overlong block; callers must split it before translating. Blocks are processed in bounded
mini-batches (default 8), preserving order and avoiding document-sized padded tensors.
`tests/unit/mt_test.py` covers no truncation, over-limit rejection, acceptance at the limit,
sentinel limits, and bounded batches using shared doubles in `tests/mt_fakes.py`.

### Note Front Matter Validation

`load_note` uses the first non-blank string from front matter `title`, then `name`.
If neither qualifies, it derives a title from the filename stem, replacing underscores and
hyphens with spaces and applying title case. Missing, non-string, and blank titles do not
raise a title-validation error. `tests/unit/io_utils_test.py::TestLoadNoteTitle` covers a
valid title, name fallback, filename fallback, numeric title, and blank title.

### Release Hygiene

`CHANGELOG.md` has no Unreleased section, so post-0.2.0 commits are undocumented, and
`pyproject.toml` still reads `0.2.0`. Cutting 0.3.0 means reconciling changelog, version,
and README/AGENTS docs.

### Development Workflow

Fresh Amp orbs install the locked development environment and Taskrail CLI automatically.
The repository's pre-commit framework installs both file checks and commit-message policy,
so generated commits follow the same Conventional Commit format as maintained history.

## Caution

- The real-model path stays untested by default. Any seq2seq change needs a run with
  `SCRIBAE_REAL_MODEL_TESTS=1`, not just the stubbed unit suite.
- Batch bounding and truncation interact: a fix on one side can silently re-break the other.
- Dependency bumps (typer, mypy) have already forced source changes; treat bumps as behavior
  changes, not chores.

## Recommendation About LLM Support

Unchanged from v0.2.0: one OpenAI-compatible seam, async calls with timeout and retries,
no provider-specific SDKs. The translation post-edit pass keeps using that same seam.

## Explicitly Excluded

- New pipeline commands.
- GPU/accelerator builds of PyTorch.
- Any hosted service surface.
